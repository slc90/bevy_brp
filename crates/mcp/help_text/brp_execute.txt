Execute a one-shot BRP method registered on a running Bevy app.

The tool forwards the caller-supplied params as raw JSON to the exact method name. A successful
one-shot call needs only that BRP request; method-not-found triggers rpc.discover to list available
names without retrying the original call. Watching names are discovered before rejection to
distinguish registered watches from unknown methods. Use brp_list_agent_tools first when the application publishes
curated descriptions and raw parameter/result schemas, and follow its result.usage guidance.

Example: {"method":"test/multiply","params":{"value":6,"factor":7},"port":15712}.
Port defaults to 15702 and accepts 1024-65534. The method name must match exactly. An omitted params field sends no
JSON-RPC params; supplied params are forwarded as raw JSON without application schema validation.
The raw BRP value is returned in result. A null or missing BRP result may omit that field.

Watching methods return unsupported_call_mode with method and port in error_info; use
world_get_components_watch or world_list_components_watch for the supported stock watches.
Other watching methods have no MCP watch entry. An unknown method returns stage=discovery
and available_methods; after a direct BRP failure, error_info also retains the original BRP
code and data plus method_error_message, which may include client guidance for missing extras
methods. If the fallback discovery
also fails, the original method error remains in error_info with nested discovery_error details.

For MCP invocation, use brp_execute for missing-method guidance, timeout handling, and BRP error
details. Direct HTTP JSON-RPC is a developer-only alternative outside MCP.

After ordinary Custom Pointer automation, call
{"method":"brp_extras/pointer_control","params":{"action":"release"},"port":15712}
and poll {"method":"brp_extras/pointer_control","params":{"action":"status"},"port":15712}
until result.phase is inactive. Release is idempotent; draining means cancellation cleanup is still
pending and new ordinary pointer input is rejected. Status returns phase, busy, pointer_id (stable
UUID or null), window (entity bits or null), generation, queued_actions, pressed_buttons
(Left/Right/Middle) and last_error (null or generation/method/window/code/message). busy=false
means no queue/timer/cleanup work, not verified UI success. Status and idempotent release retain
last_error; a new successful activation clears it. Only action=status/release is accepted, with no
extra fields. This App method needs no additional static MCP tool or default agent-tool entry.
