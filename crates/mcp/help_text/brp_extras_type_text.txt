Types text sequentially in Bevy apps via bevy_brp_extras. Each character uses a press frame followed by a release frame, with proper shift handling.

Optional `window` accepts window entity bits (u64). Omission selects PrimaryWindow, or the existing placeholder behavior in headless apps. An explicit target must have a live Window component, otherwise the request returns INVALID_PARAMS without queuing input. The whole sequence uses the window captured when the request starts, even if focus or PrimaryWindow changes. If that window disappears, remaining characters are cancelled and held keys are released to the original target to clear input state. Input never falls back to another window.

Unlike `send_keys` which sends all keys simultaneously (for chords and shortcuts), `type_text` queues characters and types them sequentially. This is ideal for text input fields that need to process each character individually.

Supported characters:
- Letters (a-z, A-Z) - uppercase uses Shift
- Digits (0-9)
- Common symbols (!@#$%^&*()-=_+[]{}|;':",.<>/?\`~)
- Whitespace (space, newline, tab)

Characters that cannot be mapped will be skipped and reported in the response.

Examples:
```json
{"text": "hello world"}           // Types 11 characters with alternating press/release frames
{"text": "Hello, World!\n"}       // Mixed case with punctuation and newline
{"text": "test@example.com"}      // Email address with @ symbol
{"text": "Az!", "window": 4294967298} // Explicit window entity bits
```

Prerequisites: bevy_brp_extras dependency and BrpExtrasPlugin registered.
