Queues a press-hold-release cycle on the App-owned Custom Pointer without moving the OS cursor or writing raw mouse events. The host must install enabled PickingPlugin and InteractionPlugin plus a picking backend. Acceptance does not prove a UI result. Holds use real elapsed time, including when virtual game time is paused.

Button options: Left, Right, Middle. Default duration: 100ms; maximum: 60000ms.
Window resolution: explicit live Window entity, then last BRP window, then PrimaryWindow. BRP positions are independent of the physical mouse and start at the origin per window. Same-window move/scroll may continue during a timed hold. Repeated holds of the same button and switching windows during a hold fail. Native Window title-bar move and edge resize are unsupported.

Examples:
```json
{"button": "Left", "duration_ms": 100}     // Click left button
{"button": "Right", "duration_ms": 500}    // Hold right button 0.5 sec
{"button": "Middle"}                       // Quick middle click (default 100ms)
```

Prerequisites: bevy_brp_extras dependency and BrpExtrasPlugin registered.

Automation cleanup: use brp_execute with method=brp_extras/pointer_control and params={"action":"release"}, then poll {"action":"status"} until phase=inactive. Input acceptance, busy=false and UI success are separate checks. Raw/native cursor consumers and official Mouse-only hover consumers require host migration; there is no raw fallback. OS foreground focus is not required by this input source; host Picking and app logic still apply.
