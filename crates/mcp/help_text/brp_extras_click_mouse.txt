Queues a Custom Pointer click at the BRP logical position. Establishes a Picking hit before Press, holds for 100ms of real elapsed time, then releases in a later Picking cycle. The response confirms acceptance; inspect application state to verify the UI action.

Button options: Left, Right, Middle

Examples:
```json
{"button": "Left"}              // Click left button
{"button": "Right"}             // Click right button
{"button": "Middle"}            // Click middle button (wheel)
```

Window defaults to the last BRP target, then primary. Waits behind earlier input and existing timed holds; later input waits for completion. Does not write raw mouse input or the OS cursor. Avoid Native Window move/resize regions.

Prerequisites: BrpExtrasPlugin, enabled PickingPlugin and InteractionPlugin, and a host picking backend.

Automation cleanup: use brp_execute with method=brp_extras/pointer_control and params={"action":"release"}, then poll {"action":"status"} until phase=inactive. Input acceptance, busy=false and UI success are separate checks. Raw/native cursor consumers and official Mouse-only hover consumers require host migration; there is no raw fallback. OS foreground focus is not required by this input source; host Picking and app logic still apply.
