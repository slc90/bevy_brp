# bevy_brp 改造执行总览

把当前 `main` 改造成独立维护、边界清楚、适合 Codex 长期开发的 Bevy 0.19 工具 workspace。学习仓库已移出本轮；普通公共 MCP 与自身诊断分开，应用日志继续保留。

完整目标与约束见 [详细总方案](bevy-brp-refactor-plan.md)。下面每份文件都包含独立的目标、范围、产出、验收和前后关系。

**顺序固定，从 01 到 17。** 每次交给 Codex 一份，完成后停止；不要把整包交成一次连续施工任务。03、06、12、15 是设计关口，具体结论经确认后才继续。

| 顺序 | 小方案 | 内容 |
| --- | --- | --- |
| 01 | [固定当前 main 的改造基线](01-baseline.md) | 记录实际起点、必须保住的功能和可复用的 MCP 对照样本，不展开学习或优化。 |
| 02 | [建立 BRP 适用的通用 Agent 工程规范](02-agent-rules.md) | 从 widgetry 选择适用规则，形成简短入口与按任务读取的工程约束，让后续改造有共同标准。 |
| 03 | [确定可复现的 Rust 工程基准](03-toolchain-design.md) | 给出精确 Rust 版本、组件、lint、Cargo 配置和验证口径的决定，确认后才实施。 |
| 04 | [统一 Rust 工具链与 workspace 配置](04-toolchain-implementation.md) | 落实已确认的工具链基准，使版本、metadata、依赖和验证入口一致，不夹带架构或接口变更。 |
| 05 | [清理已经证实冗余的仓库资产](05-repository-cleanup.md) | 删除失效历史材料和无效配置引用，保留仍承担回归验证或归属记录的资产。 |
| 06 | [确定 workspace、crate 与公共 API 的目标架构](06-architecture-design.md) | 对每个保留、合并或删除的 crate 给出明确决定，并固定依赖方向、测试宿主和消费边界。 |
| 07 | [落实新的 workspace 布局与 crate 边界](07-architecture-migration.md) | 实施确认过的目录、包结构与依赖关系，并保持尚未批准改变的公共行为。 |
| 08 | [固化架构事实与 BRP 专属开发边界](08-architecture-rules.md) | 让文档和规则准确约束新结构，避免架构只存在于方案里或被误套成 widgetry 的模式。 |
| 09 | [建立行为导向的回归验证基础](09-regression-foundation.md) | 整理单元、集成与端到端验证，让后续实现重整有可重复的行为保护。 |
| 10 | [按新规范重整 MCP 内部实现](10-mcp-internals.md) | 收敛工具框架、客户端、错误和日志实现，保留公共 MCP 行为，把内部重构与接口重设计分开。 |
| 11 | [按新规范重整 Bevy App 侧实现](11-bevy-side-internals.md) | 理清 runtime、传输和扩展方法的所有权，保护请求推进、输入、截图及动态应用方法行为。 |
| 12 | [确定面向使用者的 MCP 契约](12-mcp-contract-design.md) | 逐项决定公共能力、动态发现与执行、自诊断和应用日志边界，形成可实施的接口设计。 |
| 13 | [隔离 MCP 自诊断与公共使用接口](13-self-diagnostics.md) | 让普通构建默认不暴露 Server 自诊断，诊断构建仍可排障，应用日志不受连带删减。 |
| 14 | [实施新的公共 MCP 调用契约](14-public-mcp-implementation.md) | 落实确认过的工具集合、发现与执行方式、参数和返回约定，保持能力可达与迁移可说明。 |
| 15 | [形成 MCP 消耗归因与有依据的优化决定](15-efficiency-analysis.md) | 在相同任务下测量工具定义、响应和交互步骤，区分真实客户端消耗与服务端代理指标。 |
| 16 | [实施并复测确认过的 MCP 效率优化](16-efficiency-implementation.md) | 只落地有证据、已确认的优化，以正确完成同一任务的对照结果收口。 |
| 17 | [完成工程验收、文档与消费入口收口](17-final-acceptance.md) | 核对完整能力、工程规则、默认与诊断构建和直接消费方式，交付能够长期维护的实际仓库。 |

前序关系在各文件中说明。部分相邻方案只是统一执行顺序，并无额外技术硬依赖；仍按表中顺序交接。

本包仅包含方案，没有修改仓库，也不包含实际构建、测试或消耗测量结果。
