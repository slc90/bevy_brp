# bevy_brp · Pointer 方案总览

为 App 提供不移动系统鼠标的 Custom Pointer 普通输入，保留现有 Native Window move/resize 边界。

[完整总方案](../master-plan.md)保存本次设计正文与源码依据。以下小方案按唯一顺序执行；详细约束、实现边界和验收内容均在各自文件中。

## 执行顺序

1. [建立独立 Pointer 输入源与交接规则](01-独立Pointer输入源与交接.md)

   建立只存在于 App 内的 BRP Custom Pointer，并把激活、真人交接和退场定义成完整生命周期。 私有输入源及交接状态机、明确的取消清理责任和最小 Picking 验证基础。

2. [将移动、按键和滚轮接入同一 Pointer 队列](02-基础输入与窗口坐标.md)

   将移动、定时按键和滚轮统一接入同一 Custom Pointer，明确坐标、窗口和按键支持。 单一 Pointer 基础输入实现、可核对的窗口与坐标契约，以及不写 raw mouse 通道的测试。

3. [让点击、双击和拖动遵循真实 Picking 时序](03-点击双击拖动与跨帧生命周期.md)

   使自动点击、双击和普通控件拖动按实际 Picking 周期执行，并在结束或取消后释放活动责任。 统一的跨帧手势排程、可靠的 generation 取消与 activity 收尾，以及时序回归。

4. [对齐 BRP 公共方法、MCP 说明和兼容性](04-公共协议与MCP契约.md)

   让 App 侧 BRP 方法、MCP schema 和说明准确表达新的输入行为与生命周期控制。 可发现、可调用的控制方法，准确的参数和结果说明，以及协议一致性测试。

5. [用真实宿主验证 Pointer 隔离和交互结果](05-真实宿主与隔离验收.md)

   用分层测试证明 Custom 输入确实驱动交互、没有移动系统 cursor，并能在按需更新下完整收尾。 永久回归、真实宿主证据、已测与未测记录；不是只有请求排队成功的结果。

6. [形成可供 Widgetry 消费的固定版本](06-固定版本与Widgetry交接.md)

   形成事实说明一致、可被 Widgetry 固定消费的新 BRP 版本。 固定 release/tag 或完整 commit、配套 MCP 与消费说明、清楚的验收记录。

## 跨仓库位置

先执行 BRP 01 → 02 → 03 → 04 → 05 → 06，再执行 Widgetry 01 → 02 → 03 → 04 → 05。Widgetry 前面的本地适配并不技术依赖 BRP 发布，这里给出的是统一执行顺序；最终 Gallery 接入才要求固定的 BRP 版本产物。
