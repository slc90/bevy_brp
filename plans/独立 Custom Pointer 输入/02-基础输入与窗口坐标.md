# 02 · 将移动、按键和滚轮接入同一 Pointer 队列

## 目标

将移动、定时按键和滚轮统一接入同一 Custom Pointer，明确坐标、窗口和按键支持。

## 范围

负责 cursor/support/button/scroll 相关基础入口、窗口验证、逻辑坐标及三按钮映射；不另建 raw/native fallback。

## 预期产出

单一 Pointer 基础输入实现、可核对的窗口与坐标契约，以及不写 raw mouse 通道的测试。

## 与前后方案的关系

承接前一方案的输入源、交接和清理边界；为下一方案的点击、双击与拖动提供基础动作。

本文件是顺序执行链中的第 2 份，具体位置见 [总览](00-overview.md)。需要查看完整设计时，使用 [总方案](../master-plan.md)。

## 基线与共同约束

版本：方案草案 1，2026-10-05。

核对基线：`slc90/bevy_brp@7eb70b5d24a19b8e7480b11bc1726af4e80cce6c`（本次读取时的 `main`）；配套消费方为 `slc90/bevy_widgetry@f32f5d0452cf8d63b6d506dc1060236e70367dd5`。仓库当前 workspace 版本为 `0.2.2`，依赖 Bevy `0.19.1`。仓库内容通过 GitHub 连接器读取；Bevy 行为另外核对了上游 `v0.19.1` 源码，而不是用浮动 `latest` 猜测 API。[B1] [U1] [U2]

这是一份待实施方案。本次没有修改仓库，没有运行 Rust 编译、测试、MCP 或桌面验收。下面的 `BrpPointerState`、`pointer_control`、动作队列和生命周期状态均是本方案提出的设计，不是声称仓库已经提供这些能力。

### 共同边界

目标是让 BRP 的普通鼠标操作只驱动 App 内的一只 `PointerId::Custom`，不移动系统光标，不伪造系统鼠标按键，不把 Widgetry 的业务状态直接改成测试希望看到的结果。正常输入路径是 `BRP → PointerInput → Bevy Picking → Pointer<T> → Widget`。物理鼠标仍由 Bevy 默认输入适配器产生 `PointerId::Mouse`，不被永久禁用或替换。[U1] [U2]

用户已限定 BRP 和真人不会同时操作。本方案不扩展为多操作者并发框架，但“没有同时动鼠标”不等于“没有残留 hover”。输入交接仍须结束旧动作、停用旧虚拟位置，并处理停在窗口里的物理 Mouse 位置。输入源识别留在 BRP；Widgetry 普通控件不识别 BRP 的 UUID，也不引入 BRP 生产依赖。

**Native Window move/resize 完整保持现状。** 不修改 Widgetry 的 `crates/window/src/title_bar/drag.rs`、`crates/window/src/title_bar/resize.rs` 及其现有原生操作、鼠标释放和系统 cursor 处理；不加 Custom Pointer 拒绝分支，也不添加程序化拖窗、缩放窗口或 OS 自动化替代实现。虚拟输入不支持这些原生拖拽区域，测试必须避开。保持代码不变不代表那里会自动拒绝 Custom Pointer：当前 observer 仍可能收到虚拟 Press 并发出原生拖拽请求。这是本次明确保留的边界，不得包装成已隔离或已支持的能力。[W3] [W4]

统一的是普通鼠标类 move、button、click、double-click、drag、scroll。keyboard、IME、截图、窗口标题、原生触控板 pinch/rotation/double-tap 是各自独立的能力，不把它们硬译成 PointerAction，也不借此次改动重写它们。Table 列宽拖动、ScrollArea 滚动条拖动属于普通控件交互，**不在 Native Window resize 的例外中**。不新增可见虚拟光标、overlay 或新的公共控件。

贯穿各部分的实现契约是：同一 App 的 BRP Pointer 身份稳定；普通输入只排队为 PointerInput，在既定 Picking 阶段消费；跨帧动作绑定 generation 与活动责任；取消不冒充正常 Release，清理完成前不允许新一轮输入穿过。取消通知补全只修框架生命周期，不直接改控件业务 state。官方 Hovered/DirectlyHovered 的 Custom 适配由消费方负责，不能为了样式退回伪造 Mouse。新 `pointer_control` 经现有 brp_execute 调用，status/release 及错误快照用于交接和诊断，不把请求接受等同于 UI 成功。

整个实施顺序固定为：本仓库小方案 01 → 02 → 03 → 04 → 05 → 06，再执行配套 Widgetry 小方案 01 → 02 → 03 → 04 → 05。Widgetry 前几个方案并不技术依赖本仓库发布，这个总顺序只是为了交接清楚；Widgetry 的最终接入才真正依赖本仓库可消费的固定版本。不得用浮动 `main` 或覆盖旧 tag 完成交接。

## 方案正文

### 修改落点

主要落在 `crates/extras/src/mouse/cursor.rs`、`support.rs`、`button.rs`、`scroll.rs` 和 `mouse.rs`。删除只为真人/BRP 混合位置同步服务的 `sync_cursor_position`，用独立 BRP 位置维护替代；移动、定时按键和滚轮都进入同一个输入源与动作队列，不让每个 handler 各造一套 pointer。[B2] [B3] [B5]

普通鼠标工具不再向 `WindowEvent`、`CursorMoved`、`MouseMotion`、`MouseButtonInput`、`MouseWheel` 通道双写，不再设置原生窗口光标位置。`window_event.rs` 仍供 keyboard 和独立 gesture 使用，不能因为普通鼠标不再使用它就删除整个模块。

### 坐标与窗口约定

保留已有请求形状：`move_mouse` 的 `position` 与 `delta` 二选一；坐标和 delta 都是目标窗口客户区的逻辑像素。不是桌面屏幕坐标，也不把物理像素直接传给 Picking。`Location.target` 从明确的窗口 Entity 规范化得到；不假设所有输入都在 PrimaryWindow。

窗口解析顺序固定为：显式有效 `window` → 上一次仍存在的 BRP 目标窗口 → PrimaryWindow。显式无效 ID、Entity 存在但不是 Window、目标已销毁时返回错误，不悄悄换到主窗口。此前代码的显式目标校验只检查 Entity 是否存在，方案应补齐 Window 组件校验。`last_window` 只由 BRP 自己更新，不由真人移动修改。[B3]

每个窗口分别记住 BRP 坐标；没有历史值时沿用当前原点默认语义，但在首次 Press/Scroll 前先建立该位置并让命中管线看到它。切换窗口且没有持有按键时，结束旧窗口 hover 并建立新目标；正在 hold/drag 时不允许带着同一手势跨窗口，返回明确冲突，调用方可取消后再定位新窗口。排队动作在接收时绑定具体窗口和 generation，不能执行到一半再读取变化后的全局 last_window。

验证输入有限性以及 `current + delta` 的溢出。有限的窗口外坐标是有效输入，供移出控件和拖出窗口测试；不把它夹回窗口边缘从而改变行为。DPI 与 UiScale 的转换由既有 Bevy picking/UI 链路完成，BRP 不重复除 scale。测试至少包含原点、负坐标、窗口外坐标、两个窗口不同尺寸和非 1.0 scale。

### 按键映射和兼容边界

映射只使用 Bevy 支持的三个 PointerButton：`Left → Primary`、`Right → Secondary`、`Middle → Middle`。对应 `PointerAction::Press/Release`。`send_mouse_button` 原有的定时释放能力继续保留，其排程由后续跨帧操作部分统一承接。[U1]

当前 MCP 的 `MouseButtonWrapper` 还公布 Back、Forward，直接 BRP 请求则可接收 Bevy MouseButton 的更多变体。PointerButton 没有这些等价项。新 MCP schema 不再宣传 Back/Forward 可用于普通 Pointer 鼠标工具；直接 BRP 收到它们或 Other 时明确返回参数不支持错误。不能静默换成左键，也不能为了兼容又偷偷发 raw mouse。[B6] [U1]

当前 `send_mouse_button` 只有 `button/duration_ms/window`，语义是定时按下再释放，不存在可单独指定 Press/Release 的公开参数。保持默认 100ms、最大 60000ms 和原有字段；不为此次 Pointer 迁移顺手增加 down/up API。需要提前终止时使用新生命周期 control 的 release，其语义是取消整轮虚拟输入，不是一次正常按钮释放。[B8]

自动 click/double-click/drag 请求按 FIFO 排队，同一时刻只有一个自动手势持有该 pointer。`send_mouse_button` 建立的定时持有则允许后续同窗口 move/scroll 在到期前正常进入管线，以保留“按住再移动”的既有用法；timer 与后续移动是同一指针上的不同排程责任，不能把等待 timer 作为阻塞所有移动的队首项。相同按钮尚未释放时重新建立另一个 timed hold 属于冲突；自动手势等待现有 timed hold 结束，不偷偷释放或替换它的按钮。等待中的排队项不被之后的输入随意越过。

所有旧 timer 都必须绑定操作代数，不能误释放下一轮操作。非法按键和已知冲突在修改任何状态前拒绝；需要等前项完成才能判定的条件，在实际执行前重新校验。执行时发现目标已失效，终止受影响的操作并通过状态快照和日志记录原因，不把 accepted 误报成成功完成。

### 滚轮语义

`scroll_mouse` 保留 `x/y/unit/window`，转成 `PointerAction::Scroll { x, y, unit, phase: TouchPhase::Moved }`；沿用现有的 Line/Pixel 单位和相位，不重解释为像素滚动距离，不手工修改 ScrollPosition。先确保目标 location 已进入 Picking，再让正常命中、冒泡及嵌套 ScrollArea 处理滚动。[B5] [U1]

### 此部分的验收

产出是三个基础入口的单一 Pointer 实现与窗口/按键验证。对真实 Picking fixture 断言 pointer ID、规范化 target、逻辑坐标、动作顺序和结果；同时记录 raw mouse 通道，验证在没有真人输入时 BRP 普通鼠标操作没有向这些通道写入事件。原生 `Window` 的 cursor 位置不应因请求改变。仅断言 handler 返回了坐标不算通过。
