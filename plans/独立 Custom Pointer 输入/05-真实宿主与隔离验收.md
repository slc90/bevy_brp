# 05 · 用真实宿主验证 Pointer 隔离和交互结果

## 目标

用分层测试证明 Custom 输入确实驱动交互、没有移动系统 cursor，并能在按需更新下完整收尾。

## 范围

负责 Extras/Picking fixture、MCP 与桌面宿主、raw 通道观察、系统 cursor 只读证据和进程清理。

## 预期产出

永久回归、真实宿主证据、已测与未测记录；不是只有请求排队成功的结果。

## 与前后方案的关系

承接前四份方案已经定义的行为和协议；其证据构成下一方案发布与交接的门槛。

本文件是顺序执行链中的第 5 份，具体位置见 [总览](00-overview.md)。需要查看完整设计时，使用 [总方案](../master-plan.md)。

## 基线与共同约束

版本：方案草案 1，2026-10-05。

核对基线：`slc90/bevy_brp@7eb70b5d24a19b8e7480b11bc1726af4e80cce6c`（本次读取时的 `main`）；配套消费方为 `slc90/bevy_widgetry@f32f5d0452cf8d63b6d506dc1060236e70367dd5`。仓库当前 workspace 版本为 `0.2.2`，依赖 Bevy `0.19.1`。仓库内容通过 GitHub 连接器读取；Bevy 行为另外核对了上游 `v0.19.1` 源码，而不是用浮动 `latest` 猜测 API。[B1] [U1] [U2]

这是一份待实施方案。本次没有修改仓库，没有运行 Rust 编译、测试、MCP 或桌面验收。下面的 `BrpPointerState`、`pointer_control`、动作队列和生命周期状态均是本方案提出的设计，不是声称仓库已经提供这些能力。

### 共同边界

目标是让 BRP 的普通鼠标操作只驱动 App 内的一只 `PointerId::Custom`，不移动系统光标，不伪造系统鼠标按键，不把 Widgetry 的业务状态直接改成测试希望看到的结果。正常输入路径是 `BRP → PointerInput → Bevy Picking → Pointer<T> → Widget`。物理鼠标仍由 Bevy 默认输入适配器产生 `PointerId::Mouse`，不被永久禁用或替换。[U1] [U2]

用户已限定 BRP 和真人不会同时操作。本方案不扩展为多操作者并发框架，但“没有同时动鼠标”不等于“没有残留 hover”。输入交接仍须结束旧动作、停用旧虚拟位置，并处理停在窗口里的物理 Mouse 位置。输入源识别留在 BRP；Widgetry 普通控件不识别 BRP 的 UUID，也不引入 BRP 生产依赖。

**Native Window move/resize 完整保持现状。** 不修改 Widgetry 的 `crates/window/src/title_bar/drag.rs`、`crates/window/src/title_bar/resize.rs` 及其现有原生操作、鼠标释放和系统 cursor 处理；不加 Custom Pointer 拒绝分支，也不添加程序化拖窗、缩放窗口或 OS 自动化替代实现。虚拟输入不支持这些原生拖拽区域，测试必须避开。保持代码不变不代表那里会自动拒绝 Custom Pointer：当前 observer 仍可能收到虚拟 Press 并发出原生拖拽请求。这是本次明确保留的边界，不得包装成已隔离或已支持的能力。[W3] [W4]

统一的是普通鼠标类 move、button、click、double-click、drag、scroll。keyboard、IME、截图、窗口标题、原生触控板 pinch/rotation/double-tap 是各自独立的能力，不把它们硬译成 PointerAction，也不借此次改动重写它们。Table 列宽拖动、ScrollArea 滚动条拖动属于普通控件交互，**不在 Native Window resize 的例外中**。不新增可见虚拟光标、overlay 或新的公共控件。

贯穿各部分的实现契约是：同一 App 的 BRP Pointer 身份稳定；普通输入只排队为 PointerInput，在既定 Picking 阶段消费；跨帧动作绑定 generation 与活动责任；取消不冒充正常 Release，清理完成前不允许新一轮输入穿过。取消通知补全只修框架生命周期，不直接改控件业务 state。官方 Hovered/DirectlyHovered 的 Custom 适配由消费方负责，不能为了样式退回伪造 Mouse。新 `pointer_control` 经现有 brp_execute 调用，status/release 及错误快照用于交接和诊断，不把请求接受等同于 UI 成功。

整个实施顺序固定为：本仓库小方案 01 → 02 → 03 → 04 → 05 → 06，再执行配套 Widgetry 小方案 01 → 02 → 03 → 04 → 05。Widgetry 前几个方案并不技术依赖本仓库发布，这个总顺序只是为了交接清楚；Widgetry 的最终接入才真正依赖本仓库可消费的固定版本。不得用浮动 `main` 或覆盖旧 tag 完成交接。

## 方案正文

### 测试分层与现有缺口

当前 `docs/testing.md` 已明确：现有总回归中的输入主要检查排队结果，`cargo test --workspace` 不会自动执行 MCP→BRP→真实 UI 的完整链路。因此这次不能只更新 JSON 快照或跑原脚本就宣布点击迁移完成。[B14]

Extras 内测试负责协议验证、窗口解析、队列时序、按键 ownership、generation、取消、组件收敛和 activity。真实 Picking fixture 负责从 `PointerInput` 进入命中、hover、click、drag、scroll 的结果。MCP/桌面宿主负责验证协议表面、后台推进、原生 cursor 不移动和真实画面。三个层次都保留，不能相互替代。

### 宿主和回归落点

核对并调整 `tests/test-app/examples/mouse_test.rs`、`extras_plugin.rs`、必要的 `event_test.rs` 以及关联永久测试；它们可能显示或统计 raw mouse，不应为了旧计数继续双发 raw。新的受支持交互结果按 Pointer 计数与 UI state 观察；另设 raw 观察器验证 BRP 没写入原始鼠标通道。原有 keyboard 和 gesture 的记录保留，不混入“raw mouse 必须为零”的断言。

新增或扩展一个使用真实 Picking backend 的小型宿主，使用普通按钮、拖动目标、滚动容器和两个窗口即可，不需要复制 Widgetry 或使 BRP 仓库依赖 Widgetry。优先复用现有 `bevy_brp_test_apps` package。截图场景、同名 target 发现和日志清理不因本次变化失效。[B11] [B14]

最低自动化覆盖应包括：取消帧保留位置产生 Out/Leave、原 press/drag 目标收到唯一补全 Cancel、stock Button 取消后不残留 Pressed、正常 Release 不重复补 Cancel、以及首次 move+click、没有新 Move 的 click、左/右/中键、定时按键、多击阈值内外、最少 frames 的 drag、离开目标再取消、Line/Pixel scroll、多窗口与已销毁窗口、release 幂等、真人交接、连续多轮指针激活，以及无关 raw 通道不被清空。不能只用 `world.trigger(Pointer<Click>)` 代替这条链。

### 系统鼠标隔离如何验收

在真人不移动鼠标的受控桌面条件下，读取 OS cursor 的位置作为基线，执行 BRP 普通输入，再只读检查位置未变；这种读取是验收证据，不是 Win32 移鼠标替代输入。同时证明 UI 确实发生了预期点击、滚动或拖动。单看 ECS 的 Window cursor 没变不足以证明 OS cursor 没动，单看截图也不足以证明输入状态已释放。

光标留在其他应用区域时，BRP 仍应能驱动目标 App 中的普通控件，且不得通过激活窗口、grab cursor 或改 OS 焦点来造出结果。Native Window 标题栏 move 和边缘 resize 不作为 BRP 场景；该限制必须出现在测试记录中。

### 按需更新与回归入口

保留 `WinitSettings::desktop_app()` 和 runtime 的 wake-aware transport，不增加常驻 Continuous 或高频 Reactive 作为修复。timed click、double-click、drag 和退场必须持有实际活动责任；动作结束后 active_count 和续帧恢复基线。长时间 hover 若由 Tooltip 请求 redraw，应与 BRP 自身永久 busy 区分。[B9] [B10] [W5]

以当前工程规则执行定向 package 测试、`cargo fmt --all -- --check`、`cargo check --workspace --locked`、`cargo clippy --workspace --all-targets --locked`、`cargo test --workspace --locked --no-fail-fast`、`cargo build --workspace --locked`，并检查 Extras 的既有 feature 组合。在具备 Windows 桌面、GPU、PowerShell 7、空闲端口的环境运行相关普通/诊断 MCP 回归及新的 Pointer 场景。不要修改历史 before 样本来掩盖行为变化。[B14] [B15]

这一部分交付永久回归测试、真实宿主结果和可核查证据。截图、状态、事件轨迹、活动计数、错误以及本轮进程/端口清理各自有结论。没有环境的项记录未测；已有失败与新增失败分开。没有桌面测试时不得宣称系统 cursor 隔离已经通过。
